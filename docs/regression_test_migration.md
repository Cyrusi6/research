## M1.1.2 RouteOutcome authority and hermetic audit

- `tests/test_s3_precommit_orchestration.py::test_orchestrator_prefers_repair_route_over_blocked_result_status`, `...pause...`, and `...integrity...` used a monkeypatched `ExperimentAgent` route plus a synthetic Gate PASS. They are superseded by `tests/test_m112_orchestrator_authority.py`, which creates real reducer route events and verifies the Orchestrator against SQLite history. The old pattern is not an acceptable control-flow test because an arbitrary result payload must not control routing.
- The Experiment result identifies the committed attempt, event, and sequence. The Orchestrator calls the ledger's public `query_operation_result()` for that event, verifies its deterministic RouteOutcome remains current, and treats `result.route_outcome` as an optional diagnostic projection requiring canonical equality when present.
- Missing committed identity, stale event identity, wrong source attempt, wrong source sequence metadata, unknown action, budget mutation, and diagnostic/ledger conflicts fail closed as integrity blocks.
- Hermetic full-suite acceptance uses explicit fake Codex discovery/subprocess behavior and temporary literature/cache roots. Simulated `use_real_api=false` flows must remain independent of proxy/OpenAI variables. M1.1.2 adds no skip or xfail; the two existing optional torch/transformers skips remain the only permitted skips.
